## Plan

**The u11 decision deferred from the plan — how `{iter, params, metrics}` reaches history:**
the Trainer's prompt requires every generated script to print one line
`METRICS_JSON: {"params": {…}, "metrics": {…}}` with values **computed by the executed code**.
The harness (orchestration only) scans stdout for that marker after each execution, appends
`{iteration, params, metrics}` to `03_metrics_history.json` (written incrementally — live UI),
and emits an `iteration_metrics` event. rc==0 without a parseable marker → a `[harness]` note
in the tool result tells the agent to include it next run. Metric *values* therefore only ever
originate in the agent's own executed stdout.

1. `Sandbox.last` attribute (raw stdout/stderr/rc of the latest execution — the agent-facing
   return stays truncated; u10 API otherwise unchanged).
2. `prompts/trainer.py` — "Coder": choose target framing (its call, stated), XGBoost,
   generate→execute→READ→react; hard rule: after every execution the next text must **quote at
   least one concrete number or error line** from the output and state what it implies before
   acting; METRICS_JSON line mandatory; min 2 / max 6 executions stated.
3. `stages.py`: `trainer_stage(ctx)` — Sandbox + wrapped execute tool:
   - budget: ≥6 executions → tool refuses, tells agent to finish (loop cut, best-so-far)
   - metrics parse + history append + `iteration_metrics` event per execution
   - `finish_guard`: rejects finish while executions < 2 (explanatory tool result)
   - artifacts: `03_metrics_history.json`; handoff = engineered CSV + trainer report.
4. Tests (no LLM): `_parse_metrics_line` (good/missing/garbled) · budget-exhaustion refusal ·
   finish-guard accept/reject thresholds.
5. Real-run verification (isolated, cheap): seed a fresh run dir with u09's
   `02_engineered_data.csv` + strategy report as upstream; run `trainer_stage` alone. Assert
   from `events.jsonl`: ≥2 executions, each followed by reasoning **quoting its output**
   (shared-token check), history ≥2 entries, finish accepted. Eyeball the react cycle.

## Result

Verified 2026-06-06. **The hard part was SDK reality, found by running** (plan insight added):

- **Run 1: every one of 30 turns returned empty.** Raw-call debug → `finish_reason =
  MALFORMED_FUNCTION_CALL`: flash near-deterministically mangles large multi-line code strings
  as free-form function-call args. Fix: `force_function_calling` (mode ANY, constrained
  decoding) in `run_agent` + harness-reserved `reasoning` tool argument (logged as a
  `reasoning` event, stripped before dispatch) since forced mode suppresses text parts. The
  empty-parts recovery also names MALFORMED now. Suite stayed green (70).
- **Run 2** (`runs/u11-trainer-test`): the centerpiece, organically dramatic:
  - 5 executions, rc `[0, 1, 1, 1, 0]` — ≥2 ✓
  - every execution's next reasoning **quotes its output** (checked programmatically: shared
    concrete tokens `0.97`, `SyntaxError`, `XGBoostError`, `20`/`21` line numbers); the last
    execution's reaction is the finish report's iteration table ✓
  - `03_metrics_history.json`: 2 entries (≥2 ✓; crashed iters print no marker, by design),
    R² 0.9706 → 0.9800 with explicit param changes (max_depth 5, lr 0.1, n_estimators 200,
    subsample/colsample 0.8) ✓
  - finish accepted after guard satisfied; budget messages (`n/6 left`) in tool results ✓
  - agent quality: self-identified leakage (dropped `Total Yearly Compensation`), correct
    diagnosis of the `reg:squareerror` typo from the quoted XGBoostError.
- Guardrails (no-LLM): 9 pytest cases — parse good/last-wins/missing/garbled/partial, min-2
  finish-guard thresholds, 7th-execution refusal (file proven never written), history append,
  missing-marker note. Suite **70 passed**.
