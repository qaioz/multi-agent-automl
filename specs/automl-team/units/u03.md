# u03 — EventLog (`events.jsonl` writer, 9 event types) + console renderer

- **Status:** verified
- **Taken:** 2026-06-06
- **Plan ref:** [`../plan.md`](../plan.md) §Work units → u03 · insight #3 (SHOW-WORK falls out of
  the EventLog; console/live-UI/replay-UI are three renderers of the same bytes)

## Plan

1. `automl_team/events.py`:
   - Event shape (spec/DESIGN §4): `{ts, agent, type, payload}` — `ts` ISO-8601 UTC, `agent` the
     emitting stage (`orchestrator`, `cleaner`, `feature_engineer`, `trainer`, `report`),
     `payload` a type-specific dict.
   - The 9 types as constants: `run_meta`, `stage_start`, `stage_end`, `tool_call`, `tool_result`,
     `reasoning`, `execution`, `iteration_metrics`, `handoff`, `error` (stage_start/end = one
     pair, hence "9").
   - `EventLog(path)`: append-only writer — one JSON object per line, `ensure_ascii=False`,
     flushed per event (live UI tails the file); `emit(agent, type, **payload)` returns the dict.
   - `read_events(path)` → list of dicts (used by replay UI + tests; tolerant of a trailing
     partial line — live tailing can catch a mid-write).
2. `automl_team/console.py`: `render(event) -> str` — one compact human line per event type
   (icons per DESIGN §5: 🧰 tool_call, ↩ tool_result, 💭 reasoning, ⚙ execution, …); long
   payloads truncated. Used by headless runs to mirror events to stdout.
3. `tests/test_events.py`: round-trip every event type through write→read (exact payload
   equality, unicode survives), append-only across two EventLog opens, partial-line tolerance,
   and `render()` returns a non-empty line for every type with its key info present.

## Done when (from INDEX)
